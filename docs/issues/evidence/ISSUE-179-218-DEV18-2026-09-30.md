## Planning Change

- Keep VM quantity arithmetic BigInteger, AE2's worker pool, scheduling,
  inventory snapshot and submission ownership. No new worker pool or RPC queue.
- Native AECraftingPattern primary-key validity already has an unconditional
  AE2 acceptance branch. Answer it locally instead of reacquiring world access.
- Reuse validation by complete AEKey/NBT only within a request and only for
  exact vanilla ShapedRecipe/ShapelessRecipe plus exact vanilla Ingredients.
- Reuse remainders more narrowly, for those recipes and exact Item/BucketItem
  implementations. Unknown/custom predicates and remainder callbacks stay live.
- Read the recipe actually bound to the pattern through NativeVmRecipeView;
  do not substitute a newer recipe-manager entry for the existing pattern.
- Retain interruption checkpoints and all stock/quantity accounting. Do not
  turn unsupported custom behavior into guessed quantities or clamp quantities.

Before/fix evidence: `build/issue218-native-input-before.log` reproduced a timeout
when repeated primary queries awaited another tick. The corrected worker finishes

## Machine Change

- Full AEKey/NBT identity survives captured recipe hints. Legacy three-argument
  StackIntent construction remains available but cannot prove exact identity.
- Exact target lookup uses the six target sides, not a scan of every machine's
  hint entries. Ordinary provider throughput remains native and unthrottled.
- GT 7.5.3 resolves a unique input/output quantity-ratio match from recipes that
  its own RecipeDB accepted. Successful add/clear is observed, never replaced.
  Revision changes invalidate output and target-candidate caches. Rejected
  staging recipes and display-only entries are not treated as usable recipes.
- GT native lookup is deferred until the hinted candidate fails. Native machine
  validation, voltage, consumption and duration remain unchanged. Unsupported,
  chanced, nonconsumable or ambiguous signatures use native lookup.
- Mekanism 10.4.16.80 has a typed single-item electric-machine adapter. It uses
  full input/output identity, native input predicates and exact quantity ratios.
  Native recipe-list replacement invalidates the index. No reflective tile scan,
  getRecipe HEAD cancellation, CachedRecipe replacement or processing shortcut.
- Mekanism's lookup bypass counter is visible through `/aco stats`; no log per
  delivered item is added.

1. Class responsibility documentation initially omitted the new top-level rows;
   the gate failed, the rows were added, and the full builds passed afterwards.
2. The Mek fixture initially rejected provider input; explicit normal item-side
   configuration fixed the fixture. Machine acceptance rules were not relaxed.
3. Adding GT to the old provider world exhausted heap in AE2's debug item
   generator while enumerating GT tool variants, before tests executed. A fresh
   machines-only fixture separates this from crafting/dispatch verification.
4. The first actual GT cycle did not enter the hinted path: RecipeManager lacked
   the proxy recipe used by the native furnace. Observing accepted native DB
   registrations fixed the lookup source. The same GT cycle then passed.
