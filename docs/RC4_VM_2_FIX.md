# rc.4 + VM 検証版2

過去のvm.2調査記録です。ここにある導入JARと症状は現在のものではありません。
現在の構成・制限・公開判断は`issues/ISSUE-208.md`を参照してください。

## 確認した原因

2026-09-23 00:40:03 に至高回路1個の計算開始、00:40:35 に失敗。
`branching planning work limit exceeded` が原因です。
VMではなく、分岐計算の累計1,048,576回の制限で終了しています。

両環境の導入JARは、バージョンが末尾で重複する中間ファイルでした。
SHA-256: `090DA10744F99FBDE7A5D6C7C945A8D934339D9927C672012C0D34135B29C0F4`
このファイルにはVMライブラリもJar-in-Jarメタデータもありません。
以前リンクした配布JARには含まれますが、似た名前を同じフォルダに出した点を修正しました。

## 今回の修正

- 累計処理回数だけで注文を終了する条件を削除。
- キャンセル・制御返却、木のノード数・深さの上限は維持。
- 診断用intカウンタの桁あふれを防止。数量のBigInteger正本は変更なし。
- 計算経路・VM計算実施をINFOログに出力。分岐計算は5秒間隔で継続状態を記録。
- 配布用を `build/distributions`、中間JARを `build/intermediates/jars` へ分離。
- rc.5の反復最適化、新注文UI、通信変更は追加していません。
