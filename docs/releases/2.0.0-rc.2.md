# AE2 Crafting Optimizer 2.0.0-rc.2

## Prerelease / プレリリース

This candidate adds reusable processing byproducts to the compiled planner.
Back up your world/config and install the matching ACO version on server and clients.

加工の複数出力を同じ発注内で再利用する計画に、高速計算の対応範囲を広げた候補版です。
導入前にワールド・Configをバックアップし、サーバーとクライアントのACOを揃えてください。

どちらもMODバージョンは **2.0.0-rc.2** です。末尾はMinecraftのバージョンです。

## Improvements / 改善内容

- When one process produces A+B and later steps need both, credit both outputs
  after the inputs and reuse the available output without duplicating the process.
  For example, `raw -> A + B` followed by `A + B -> result` needs one processing
  operation per result, not two.
- Preserve AE2 input order, rounded surplus and partial initial stock. Reserve
  only the peak deficit from initial inventory, never generated stock as initial stock.
- Track the actual request order and input-template units for CPU byte accounting,
  including shared dependencies inside these supported byproduct graphs.
- Use bulk quantities rather than a loop for every item. Keep checked long
  boundaries and BigInteger promotion, including otherwise-unused output overflow.
- Preserve full item NBT/component identity and fluid quantities. The evaluator
  remains AEKey-generic; this is not a separate Mekanism recipe implementation.
- Include the same accounting in shadow comparison and program invalidation.

- 同じ加工からAとBが出て、その両方を後続工程で使う場合に、副産物・余剰分を再利用。
  A用とB用で加工を二重に数えない計画に対応しました。
- AE2の入力順、端数による余り、手持ちの一部在庫を考慮。
  加工で生まれる分を、最初から持っていた在庫として予約しないようにしました。
- 対応する複数出力のグラフでは、共有中間素材も含めて要求順を記録し、
  CPU容量を計算します。液体などの入力単位も保持します。
- 個数分の繰り返しではなく数量をまとめて計算。
  未使用の副産物を含め、long超過はBigIntegerへ引き継ぎます。
- NBT・コンポーネント違いと液体量を保持。同じ処理をAEKey単位で使い、
  Mekanism自体のレシピ・機械動作は変更しません。
- 標準AE2との比較処理と、入力単位が変わった際の計画失効にも対応しました。

## Scope And Verification / 対応範囲と検証

Supported: acyclic graphs with one producer per requested key and one exact
input alternative per slot. Existing independent-output planning remains intact.
The tests invoke the actual AE2 calculation and compare pattern counts, initial
reservations, missing ingredients and bytes, including 500 seeded shared-graph cases,
fluid-template boundaries and distinct NBT/components. BigInteger tests include 10^64 orders.

対象は、循環がなく、各素材の加工候補と各入力スロットの候補が一つに確定する計画です。
従来の独立した副産物の対応も維持しています。
AE2本体の計算を直接呼び出し、加工回数・予約在庫・不足・CPU容量を比較しています。
500種類の共有グラフ、液体の入力単位、NBT等の区別に加え、10^64数量の計算も試験します。

Cycles/returned catalysts, ambiguous producers, dynamic recipes and returned
containers remain outside this fast route. Missing-material CRAFT_LESS searches
on the new route defer to AE2 before custody when long-compatible; unsupported
wide plans are explicitly declined, never truncated.

循環・返却触媒・複数の加工候補・動的レシピ・返却容器は、この高速経路の対象外です。
不足時に「作れる分だけ」を探す新経路は、通常数量なら所有権移転前にAE2へ戻します。
対応できない巨大数量は、切り捨てず明示的に拒否します。

AE2 is required; other integrations remain optional. Forge targets AE2 15.4.10
and is checked against 15.5.0-uelm; NeoForge targets AE2 19.2.17.
No Minecraft launch, deployment, live industrial completion, cancellation refund,
restart recovery or modpack speedup is claimed by these automated tests.
Real Mekanism chemical/add-on execution also needs live validation.

AE2が必須、他の連携MODは任意です。ForgeはAE2 15.4.10 / 15.5.0-uelm、
NeoForgeはAE2 19.2.17を対象に試験します。
今回の自動試験は、起動・配置・実ワールドの工業クラフト完了・取消返却・再起動復旧・
計算時間短縮を証明するものではありません。MekanismのChemicalや外部CPUでの
実動作も実機検証が必要です。

No recipes, CPU ownership, receipts or persistent job formats are changed.
レシピ、CPUの所有権、Receipt、永続ジョブ形式は変更していません。

[Issue #185](https://github.com/syarukasu/ae2-crafting-optimizer/issues/185) stays open
for remaining scope and live verification. See [rc.1 notes](2.0.0-rc.1.md) for
the inherited 2.0 API/migration changes.
残る対応範囲と実機検証はIssue #185で継続します。2.0のAPI移行上の注意はrc.1を参照してください。
