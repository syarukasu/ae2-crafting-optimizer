# ACO 2.0.0-rc.6-rc4-vm.6 (Forge 1.20.1 prerelease)

## 修正

- `.5`で至高量子制御回路1個の計算が`VM capture resident limit exceeded`で失敗した問題に対応。
- 注文数と無関係に、返却された道具の将来の耐久値・NBT状態をすべて列挙する処理を撤去。実際の計算で使う素材候補だけを取得します。
- 不要な製造方法の返却物や、入力×全在庫候補の組合せを先回りして展開しません。候補順を維持し、必要量を満たした時点で残りの候補調査を止めます。
- 素材判定はサーバースレッドの小さなバッチで取得し、注文内で再利用。1バッチは最大128件・コールバック間で2msを目安に区切ります。単一MODコールバックの強制中断はしません。
- 取消状態を保持し、ワーカースレッドの割り込み解除後に取得処理が続く競合を修正。
- 数量はBigIntegerのまま。NBT、代替素材の単位、返却物、在庫予約量、提出前の再検証は省略しません。保持データの安全上限を単純に増やした修正ではありません。

## 個別計測

管理者用の`/aco vm recent`を追加。直近64件から、注文番号・アイテムID・注文数・計算結果・所要msを確認できます。`/aco vm recent 64`で最大件数を表示します。

- `ready`: 実行可能な計画を構築。物理クラフト完了ではありません。
- `missing`: 不足素材を含む計画を構築。
- `failed` / `cancelled`: 計算失敗 / 取消。
- 時間には素材情報の取得待ちを含み、ワーカーの実行開始前のキュー待ちは含みません。
- 注文ごとのログスパムは復活させません。全注文の平均値を特定の回路の時間として扱わないための機能です。

## 検証範囲

旧実装で失敗する長い返却状態列・未使用製造方法の試験を作成してから修正。1,024製造方法×2,048在庫候補の合成試験は、再検証を含めて2,304回の素材判定で正しい数量を計算しました。

数量1、2、Long.MAX_VALUE、MAX+1、10^64と返却周期、空/一部/十分な在庫、サーバースレッド限定アクセス、分割処理、取消、判定変更時の拒否を検証しています。既存の実AE2比較試験も維持します。

ローカル単体試験は662件中656件成功、既存の任意依存試験6件スキップ、失敗0件。通常AE2 15.4.10とUELM 15.5.0で、それぞれ8件のGameTestと同梱JAR検査に成功しています。

**これは本番の至高回路の速度測定ではありません。** 修正版を本番へ適用しての再注文は未確認です。全工業レシピでの速度保証、10秒未満の最終目標、すべての外部CPUでの巨大注文実行・復旧を保証する版ではありません。

今回は本番JARの変更・停止・再起動を行っていません。
