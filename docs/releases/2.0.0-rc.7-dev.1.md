# ACO 2.0.0-rc.7-dev.1: local acceptance candidate

This is NOT ACO 2.0.0 stable and has NOT been published or deployed. The server
and client are unchanged. Tracked by [Issue #218](../issues/ISSUE-218.md).

## Changes

- Keep the external BigInteger API binary surface while allowing internal
  planner replacement. Expose exact results through their owner instead of
  selecting a concrete planner class inside the public API.
- Remove the unused legacy capture graph. Discover recipes only when their
  output is still needed after consuming intermediate stock.
- Preserve AE2 requester ownership and input semantics. Combine recipe metadata
  reads into bounded server visits; arithmetic remains on the calculation worker.
- Use an exact lookup for verified native processing inputs, preserving NBT and
  fluid identity. Custom predicates and returned items still use server callbacks.
- Block a stable numeric release when its scope contains pending runtime checks.

## Verification

AE2 15.4.10 and UELM 15.5.0-uelm each passed 697 JUnit tests (no skips), 8 real
AE2 GameTests, and the nested-JAR audit. The optional AQE/EAEP/NeoECO tests use real
JARs, but do not prove those mods working together in a launched pack.

Synthetic operation counts improved from 2,049 observations to 1 for an exact
processing input with 2,048 wrong-NBT stock variants, and from 5 server visits to
3 for a one-pattern request. These numbers are NOT production latency gains.
See the Issue document for artifact hashes and archived evidence paths.

## Not complete

- Wide processing-machine and interleaved/cyclic plans still exceed the existing
  receipt executor's supported input/step contract. A correct plan is not an
  executable or completed order.
- Production large-job completion, cancellation/refund, restart/recovery and
  simultaneous-order accounting have not passed for this candidate.
- The creative-circuit empty/partial/full stock matrix and <10 s final target
  have not been measured. Server I/O work is not claimed to be zero.
