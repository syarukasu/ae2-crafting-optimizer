# ACO 2.0.0-rc.6-rc4-vm.4 / Forge 1.20.1

rc.4を土台に、VMを計算エンジンとして使う構成へ整理したプレリリースです。
対応する通常AE2は15.4.10、UELMは15.5.0-uelmです。1.21.1版ではありません。

## 変更点

- VMフォークのネイティブ計算モジュールとBigInteger計算ライブラリをJar-in-Jar同梱。
- パターン取得・レシピ展開・数量計算をVM側へ集約。
- ACOの重複した「グラフをVMへ変換する処理」を削除。
- VMの計算結果を受け取る際、ACOが再度longで数量を掛け算して失敗する不具合を修正。
- 注文数・素材数・不足数・パターン回数・容量の正確な値を既存BigInteger APIへ公開。
- 作業台向け実行の準備を計算完了条件から切り離し、既存の実行側へ移動。
- 通常クラフトで配送先の順番を壊していた旧ACOの実行回数調整を、VM使用時に無効化。
- 既存の取消・返却・保存と、入力の二重確保を防ぐ処理は維持。

## 検証範囲

通常AE2／UELMともに単体試験632件中626成功・6件スキップ・失敗0件、
重点GameTestは各8件成功。Jar-in-Jar内容とリリース対象の回帰台帳も検査済み。

数量1、2、long上限、long上限+1、10^64について、在庫なし・一部あり・全部ありを比較。
入力係数自体がlong上限の二乗になる場合も、VMからAPIまで数量が一致することを検証。
実AE2の加工完了、返却容器、取消、同時注文の予約、在庫変化、巨大不足計画、
素材が足りる巨大計画のAPI受け渡しをGameTestで確認します。
最後の巨大計画の試験は計算とAPI受け渡しの試験で、巨大加工の実行完了試験ではありません。

## 制限

**BigInteger APIへの受け渡し成功と、全CPUでの巨大加工注文の実行対応は別です。**
既存のACO Receipt実行とそれを利用するAQEの経路は、固定入力の非循環な作業台工程が対象です。
longを超える加工機械・動的入力・循環工程の実行範囲は、この版では拡張していません。
対応していないCPUへ丸めた数量で注文を通すことはしません。

BigInteger注文数を直接入力する新GUI、実環境のクリエイティブ制御回路の10秒目標、
サーバー負荷の実測改善、巨大工業注文の完了・取消・再起動復旧は未検証です。
本番サーバー／クライアントへの配置や起動は、この公開作業では行っていません。
