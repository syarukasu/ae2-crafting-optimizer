# AE2 Crafting Optimizer 2.0.0-rc.3

## Prerelease / プレリリース

This is a test release of the merged #190 planner fixes, not a claim that every industrial recipe is accelerated or that the full creative-control-circuit tree completes planning within 10 seconds.
Issue #190 remains open. Back up your world/config and use the matching ACO version on server and clients.

Issue #190で修正した計算処理をまとめた試験版です。全工業レシピの高速化や、クリエイティブ制御回路の全工程を10秒以内で計算できることを保証する版ではありません。
Issue #190は継続します。ワールド・設定をバックアップし、サーバーとクライアントのACOをそろえてください。

## Improvements Since rc.2 / rc.2からの改善

- Extend exact ordered planning to single-output recipes that share intermediate materials. Preserve input order, reuse rounded surplus and count CPU bytes from the actual request trace.
- 同じ中間素材を複数の工程で使う単一出力レシピにも高速計算の対応範囲を拡大。入力順・余剰素材の再利用・必要CPU容量を正確に扱います。

- Prune dependencies supplied by captured emitters before cycle validation, and stop later snapshot checks from rejecting their unused producers. Actual dependency cycles remain guarded.
- 要求時に供給する素材について、使わない製法が原因で循環扱い・計画拒否になる問題を修正。実際に使う経路の循環チェックは維持します。

- Fix the legacy map planners counting simulated byproducts or surplus as initial stock. They now track the peak deficit from the original inventory; their unproven fallback remains non-authoritative.
- 従来のMap方式の計算で、加工によって生まれる副産物や余剰分を元在庫として数える不具合を修正。未検証の旧経路を正式な計画として採用する変更ではありません。

## Verification / 検証

Added 250 seeded shared-input cases and 24 repeated-fluid-template cases against actual AE2 plans, comparing process counts, used inventory, shortages, emitted quantities and CPU bytes. Boundary tests include 9220000000000000000, Long.MAX_VALUE, Long.MAX_VALUE+1 and 10^64, plus immutable concurrent planning and cancellation.
Full automated suites cover upstream AE2 and UELM on Forge, and AE2 on NeoForge.

共有素材250ケース・液体の重複入力24ケースを追加し、AE2本体の加工回数・消費在庫・不足・供給要求・CPU容量と照合しています。
922京、longの上限前後、10^64の数量、同時計算でのスナップショット非変更・計算取消も試験します。
Forgeの通常AE2／UELMとNeoForgeを自動試験の対象にしています。

## Limits / 既知の制限

The authoritative fast route still requires a proven acyclic graph, one producer per requested key and one exact input alternative per slot. Ambiguous producers, returned catalysts/containers and dynamic recipes remain outside this route. The bounded ordered evaluator does not imply linear work for every shared graph.
No changes to recipes, CPU ownership, receipt formats or persistent jobs. No JVM/GC fix is included.

高速経路は、使用経路に循環がなく、製法と各入力候補が一つに確定している計画が対象です。複数製法の選択・返却触媒や容器・動的レシピには未対応部分があります。あらゆる共有構造を一定の速さで処理できるという意味ではありません。
レシピ、CPUの所有権、Receipt、保存済みジョブの形式は変更しません。JVM・GCの修正も含みません。

Automated tests and artifact checks do not prove live industrial completion, concurrent reservation safety, cancellation refunds, restart recovery or modpack latency. These remain separate runtime acceptance work.
AE2 is required; other integrations remain optional. The 2.0 API/migration notes from [rc.1](https://github.com/syarukasu/ae2-crafting-optimizer/releases/tag/v2.0.0-rc.1) still apply.

自動試験・JAR検査は、実際の工業クラフト完了、同時予約、取消返却、再起動復旧、実環境での速度改善を証明するものではありません。これらは別途実機確認が必要です。
AE2が必須で、他の連携MODは任意です。2.0のAPI移行についてはrc.1の注意事項も適用されます。
