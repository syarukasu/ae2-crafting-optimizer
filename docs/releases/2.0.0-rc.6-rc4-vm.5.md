# ACO 2.0.0-rc.6-rc4-vm.5 (Forge 1.20.1 prerelease)

## Changes

- クラフト計算で使っていたrc.4由来の`ExactBranchVM`を削除。同梱VMフォークのコンパイラーとBigInteger命令実行へ切り替えました。
- 注文数、入力係数の積、必要素材、不足、副産物、返却物、クラフト回数、容量計算をBigIntegerで扱い、計算途中で`Long.MAX_VALUE`に丸めません。
- VM本家の一回分の結果を単純に倍化する方式では、AE2との照合で19ケースの不一致がありました。入力順序、代替素材の単位、返却容器、製造方法の試行と巻き戻しを扱う命令へ拡張しました。本家の処理を無変更で使っているわけではありません。
- 反復処理は、在庫比較の結果が変わらない範囲だけまとめます。再利用する触媒や耐久値が変わる道具も、必要な元在庫を過少・過大に数えないようにしました。
- パターン取得・再確認のサーバースレッド往復をまとめ、分岐ごとの在庫全体コピーを変更分だけのコピーにしました。計算本体はワーカースレッド、ワールド参照はサーバースレッドです。
- パターン更新時の3回打ち切りを撤廃。取消可能な待機を挟んで取り直します。通常の在庫変動だけでは計画を破棄しません。提出時の実在庫予約は維持します。
- 通常注文ごとのログを抑制し、活動集計は最大60秒に1回、遅い処理のサンプルは種類ごとに最大30秒に1回へ制限しました。例外は隠しません。
- ACOは正確な在庫会計と既存BigInteger APIへの結果受け渡しを担当します。加工機への物理搬入出や外部CPUの所有権は変更しません。

## Verification And Limits

- ローカル単体試験: 654件中648件成功、既存の任意依存試験6件スキップ、失敗0件。
- 通常AE2 15.4.10 / UELM 15.5.0で各8件のGameTest成功。完了、取消、同時予約、在庫変更、BigInteger不足計画を含みます。
- 実際のAE2計算との照合には500種類の共有レシピツリー、代替製造、NBT、液体・バケツ、副産物、返却容器、容量を含みます。
- 数量試験は最大`10^1024`。代替製造・副産物再利用・触媒・耐久道具の反復は`10^64`でも検証しました。これは計算試験であり、その数量の物理クラフト完了試験ではありません。
- Jar-in-Jarの内容、ライセンス、入れ子JARの一致を検査し、旧`ExactBranchVM`が同梱されないことを検査しています。
- **未確認**: 本番サーバーでの同梱JAR起動、至高・クリエイティブ制御回路の待ち時間と負荷、全種類の外部CPUでの巨大注文完了・再起動復旧、10秒未満の最終目標。
- サーバー負荷ゼロ、全工業レシピでの最速、任意の巨大注文の物理実行を保証する版ではありません。安全上の入力・通信・CPU容量制限を撤廃する版でもありません。
- 今回は公開とJARの用意のみ。本番サーバー・クライアントの更新や再起動は行っていません。

## Installation

インストール用は`aco2.0.0-rc.6-rc4-vm.5_1.20.1.jar`だけです。VMフォークをJar-in-Jar同梱しているため、別のAE2-VM JARを追加しないでください。`sources.jar`はソース提供用で、modsへ入れません。
